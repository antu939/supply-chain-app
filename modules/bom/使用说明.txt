BOM 工作台 · 公司合规四色状态与下游追溯版（v7.2）

【v7–v7.2 修改范围】
1. 公司合规由分数改为四色状态：严重违规（红）、违规风险（黄）、合格（绿）、
   尚未核实（灰）。新建/编辑公司、公司总览、公司详情与关系图中的公司标识统一使用。
   没有填写时默认灰色「尚未核实」；没有资料既不代表合格，也不代表违规。
2. 市场合规准入页自动提示已知上游风险：选择成品公司后，沿当前 BOM 供货关系
   向上游遍历；存在红色状态时显示紧凑提示「发现上游合规异常」，并附带黄色
   「违规风险」数量。该提示不调用 AI、不改变准入状态，也不会占据列表界面。
3. 数据版本升级 v7。旧合规分数按 <60 严重违规、60–74 违规风险、≥75 合格迁移，
   原分数保留为 legacyScore 供追溯。
4. 公司总览新增「追溯下游」：进入后点击任一家公司作为起点，自动隐藏无关公司，
   只显示起点及其下游供货链；系统按下游方向重新分层排版并绘制细线箭头，
   最终成品公司标记为 ROOT。顶部可「重新选择」或「退出追溯」；
   公司详情面板中也提供「追溯下游」入口。
5. BOM 结构页新增「纵向 / 横向」布局切换。纵向时父组件在上、子组件在下，
   端口移到底部/顶部，连线从底部指向顶部；横向时仍为父右 → 子左。
   切换只改变视图坐标，不修改父子关系、供货关系、公司或工厂数据；
   切回原方向会恢复之前的手动布局，需要重排时点「整理布局」。

【第三页：五个主要元素】
1. 评估主体：仅能选择当前 BOM 成品节点已关联的公司。
2. 目标市场：可在中国大陆、欧盟、美国、英国、日本、韩国、加拿大、澳大利亚、印度之间切换。
3. 准入状态：待核实 / 符合已核验要求 / 存在准入障碍。
4. 关键证据：人工添加、编辑、删除；可记录名称、摘要、来源。
5. 关键待核实事项：人工添加、编辑、删除；可记录名称和核实内容。

【使用步骤】
打开 index.html，在顶部选择「市场合规准入」→ 评估主体 → 目标市场。
点击「添加证据」「添加事项」录入资料后，人工调整准入状态，最后点「保存评估」。
数据按 BOM × 评估主体 × 目标市场 分别保存；可在不同公司和市场之间切换。
如有未保存的修改，切换时会要求确认；顶部可使用撤销/重做。

【准入约束】
* 无打分、进度条、风险类别加权或系统建议结论，也没有 AI 核验按钮。
* 未录入关键证据时，只能保存「待核实」。
* 还有未解决的待核实事项时，不能保存为「符合已核验要求」。
* 判定和资料录入都由人工负责；条目的真实性与法规适用性须由评估者核对。
* 「符合已核验要求」仅表示人工确认当前已核验的要求，不构成法律保证。

【历史项目兼容】
沿用原有本机存储键 bom-flow-sim-v5，首次读入旧版时会保留迁移前的本机备份（v7 为 before-v7）。
旧版每个 BOM 的 risks 分数及公司档案 compliance 分数保留在备份中，但不会导入准入结论。
本版 JSON 导出格式为 v7，保留了 BOM / 公司 / 工厂 / 供货关系等数据；旧合规分数会转为四色状态并保留 legacyScore。
同名公司合并时，市场记录会迁移到保留主体；同市场冲突会合并条目并退回待核实。

【运行和测试】
无需安装环境，使用现代浏览器打开 index.html 即可（浏览器须允许本地存储）。
已安装 Node.js 时，在项目根目录运行：node tests/regression.js

以下为原项目 v5 的使用说明，部分功能（尤其风险分界面与公司合规分数）已由 v6/v7 替换，仅供历史参考：

BOM 工作台 · 公司合规与成品供应链风险版（v5）

一、打开项目
  解压后打开 bom/index.html（Chrome / Edge / Safari）。不需要服务器或安装依赖。
  当前项目数据保存在浏览器本地。如果正在使用上一版，建议先备份旧工作区；
  替换原位置的项目文件时，更有可能继续读取同一路径的浏览器本地数据。
  如果改为全新目录，不同浏览器可能将它当作不同的存储位置。

二、内置示例供应链「智能网关 G200」
  第一次打开新版时，会自动载入一套可直接修改、用于模拟的完整供应链：
  · 成品：智能网关 G200（工业级边缘网关），最终组装公司为杭州智联科技。
  · 规模：21 个组件位置、21 家公司、25 座工厂、21 条公司供货关系、23 条工厂路径。
  · 主结构：主控模组 / 电源模组（双供应商）/ 通信模组 / 结构件 /
    线束与连接器 / 包装材料 / 散热组件。
  · 供应链深度：通信模组 → 基带芯片 → 封装基板 → 覆铜板，共 5 层（含成品）。
  · 公司覆盖：上海华晶（SoC 晶圆）、深圳芯联（主控封测）、东莞恒力与佛山创能
    （电源双来源）、上海联讯（5G 模组）、苏州精工（结构件）、深圳基板（封装基板）
    等，覆盖深圳、上海、苏州、东莞、无锡、宁波、新竹等地。
  · 有意保留的模拟缺口，便于练习风险识别：
    - 包装材料尚未关联公司；
    - 散热组件已关联深圳散热科技，但尚未建立供货关系；
    - PCB 板的供货关系尚未指定工厂路径；
    - 江苏江铜线缆尚未填写合规评估；
    - 深圳芯联（RoHS 报告过期）、苏州绿环（排污许可临期）合规待整改；
      另有 6 家上游公司合规需关注。
  · 成品风险评定已预置为 68 分（高风险），类别为供应中断、质量与合规、
    地缘与政策、信息透明，并附有人工评定说明，可直接在「供应链风险」中复核、修改。
  · 上述数据保存在独立的新版本地存储键中；上一版本机工作区不会被覆盖。
    如果检测到旧工作区，右上角「…」会多出「载入上一版本机工作区…」入口。
  · 随时可通过右上角「…」→「载入示例供应链…」恢复示例；该操作可撤销。
  · 内置数据源：js/sample-data.js（应用加载）与 data/示例供应链-BOM.json（可导入）。
  · 注意：示例中的公司名称、联系人、信用代码与认证信息均为模拟数据，
    仅用于演示供应链结构与风险识别，不代表真实企业或真实供应关系。

三、正确的三层数据设计
  1. 公司主体：全局唯一，统一在「公司总览」维护名称、地址、联系人与工厂。
  2. 组件引用：A / B / C / D 每个节点独立选择引用哪些公司。
     同一家公司可以同时被 B、C、D 引用，且公司总览中只显示一份档案。
     复用组件定义不会擅自把旧节点的公司引用带过来。
  3. 供货关系：只存在于具体的组件连线上，不因为同一家公司的复用而自动生成。
     例如 A→B / A→C 分别编辑各自的接收方、供应方和工厂供货路径。

四、添加或复用公司
  1. 在 BOM 结构中选择节点，点击「公司管理」→「添加公司」。
  2. 已存在的公司：选择「复用已有公司」，搜索整个公司总览并选择已有主体。
     同一组件不会重复引用同一个公司 ID。
  3. 不存在的公司：选择「新建公司档案」，填写基础资料；
     系统会按公司名称进行全局比对，含大小写、全半角和空白字符归一化。
     如发现同名档案，会禁止重复创建并提供「复用这家公司」入口。
  4. 返回 BOM 画布，点击具体连线的「关系」按钮，建立供货关系。
  5. 从当前组件解除公司关联只影响当前组件及邻接连线，不删除公司总览主体。

五、公司合规评估（可选，不强制填写）
  1. 新建或编辑公司档案时，在「合规评估」区域填写：
     · 合规分数：0–100，分数越高越合规；留空表示未评估。
     · 合规 / 不合规原因：主要填写资质缺口、审核结论、整改事项等。
     可点击「优秀 95 / 良好 80 / 关注 65 / 待整改 40」快速填入代表分数。
  2. 不填写也完全不影响 BOM、公司与供货关系的正常使用。
  3. 公司总览卡片会显示已评估公司的分数；工具栏「合规」可筛选
     「需关注（低于 75 分）/ 未评估」，排序支持「合规分（低→高）」。
  4. 点击公司卡片，右侧抽屉的「合规评估」展示等级、分数条、原因与更新时间。
  5. 「检查当前 BOM」会提示合规分低于 60 的公司及尚未填写合规的公司数量。

六、成品的供应链风险识别
  1. 顶栏点击「供应链风险」，或用 BOM 成品节点底部的「风险」按钮进入。
  2. 评估对象是成品节点关联的最终组装公司；成品关联了多家公司时，
     可在页面顶部逐个切换，每家公司的评定分别保存。
  3. 页面会结合以下结构信息给出「系统建议分」和「识别依据」：
     · 组件是否关联公司、组件连线是否建立供货关系、是否指定工厂路径；
     · 上游公司合规分数、未评估数量、合规待整改数量；
     · 上游公司数量（是否单一来源）、供应集中度、地区集中度、层级深度。
  4. 人工评定：
     · 拖动滑杆或直接输入 0–100 的风险分数（分数越高风险越大）；
     · 多选风险类别：供应中断、质量与合规、交付与产能、地缘与政策、
       财务与信用、信息透明、供应集中、物流与仓储；
     · 可填写评定说明；点击「采用系统建议」可一键填入建议分与类别；
     · 点击「保存评定」按当前 BOM 与公司保存，可再次修改或清除。
  5. 右侧「上游公司合规概览」可直接点击公司查看资料，或点铅笔快速补填合规，
     修改后识别依据与建议分会立即更新。
  6. 风险评定随项目备份一起导出 / 导入，并受撤销、重做保护。

七、修复旧版已重复的公司
  1. 在「公司总览」查看上方是否出现「发现同名公司档案需要审查」。
  2. 点击「审查」，检查每份档案的地址、联系人、引用组件与工厂数量。
  3. 仅在确认它们属于同一个法律主体时，选择主档案并勾选确认，进行合并。
  4. 合并后保留原组件引用与各自连线关系；所有工厂记录会改为归属主档案。
     原始被合并的公司详情保存在项目数据 mergedCompanyArchives 中，
     在主公司详情面板的「同名档案合并记录」中也能查阅。
     合规评估与供应链风险评定会一并归到保留的主档案。
  5. 如果同名但并非同一家法律主体，不要合并。可核对正式注册全称，
     再对不同的主体进行命名区分。历史重复数据不会自动覆盖或丢弃。

八、备份与迁移
  · 右上角「…」→「导出项目数据备份（JSON）」下载完整工作区。
  · 「导入项目数据备份（JSON）」会【替换】当前工作区，而不是追加。
    导入时会再次显示确认，且尝试把导入前工作区保存到本地备份键。
  · 当前版本使用新的本地存储键，示例与模拟编辑都保存在其中。
    上一版数据仍保留在原存储键中，可通过「…」→「载入上一版本机工作区…」恢复。
  · 打开 v1–v4 本地数据时会自动转为 v5 内存结构。
    公司合规默认「未评估」，成品风险评定默认为空，不会丢失原有数据。
  · 旧版 localStorage 数据在首次升级时会尝试保留 before-v5 备份。
  · 浏览器本地存储并不等于外部文件备份；请定期导出 JSON 文件。

九、回归测试
  有 Node.js 环境时，进入 bom 目录运行：node tests/regression.js
  覆盖全局查重、组件复用、连线隔离、工厂路径、旧版迁移、重复公司合并，
  合规分数范围、风险类别与引用校验、合并后的风险改指、v4→v5 迁移，
  以及内置示例供应链的完整性与复杂度校验。
