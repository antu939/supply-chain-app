## 数据流与共同根因

- 生产曲线按自然日积分，批次占用半开生产区间 `[startDate, endDate)`。批次数量由 `WorldModel.getBatchQuantity` 取得，优先使用有效完工事实或明确录入数量，再回退至产出曲线积分。生产待释放按批次累计，释放时销掉本批次累计，并按批次权威数量入可用库存。原版从工厂共同的待释放量扣减实际产量，实绩低于曲线时可留下虚假的残量。本轮回归中原版残量为 18 件，修复后为 0。
- 库存锚点采用**锚定日开盘可用／可售余额**。锚点前已发货的工厂出库视为已反映在期初余额。历史货物在锚点前已可售时由市场期初余额承接。锚点前一日上架且恰于锚定日可售时，锚定日计入一次 D+1 转换。锚点前盘点由锚定余额承接。
- 日内先转换 D+1 可售并释放工厂产出，再校验和执行发运、匹配市场当日需求，最后结算实际盘点。当天发运且当天上架的零时长线路先扣工厂，再记上架。确认实发但模型余额不足时，沿用此前事实优先机制，并将缺额计入明确的库存调整和异常。
- 原版在日期解析时用计划日期判定已发运，在日终结算时才知道发运是否执行成功。节点日结、市场汇总、看板和快照各自依据不同的日期字段或状态集合聚合。发运从有效上架日就被移出物流桶，而可售从次日开始，造成遗漏和重复。
- 修复后先解析计划、实际、重算预计和推演日期，再执行供需结算，最后按执行结果和基准日事实划分库存状态、过滤路线和输出预警。下游已确认事实可以作为此前移动的凭据，未填的实绩日期保持空值。确认发运会保留可取得的计划离港日。显式改期继续使用原来的 `originalPlan` 与 `revisedEstimate`。
- AI 查询使用相同日终和作用域汇总。按自然日查询曲线时将用户的包含末日转换成积分的右开边界。批次数量聚合使用同一完工事实投影及曲线积分，统计在分页前完成。

## 状态与 KPI 口径

| 状态或指标 | 数量来源与边界 |
| --- | --- |
| 日终可用库存 `currentAvailableInventory` | 工厂可发与市场可售日终池，已结算当日转换、消耗、发运及盘点。工厂筛选取指定工厂的仓点余额；市场筛选取指定市场的仓点余额 |
| 实际在途 `currentInTransit` | 截至基准日有实际离港凭据，尚未确认抵港、放行或上架的货量。包括实际已发、抵港逾期的货量 |
| 待清关／待上架 `awaitingCustoms` | 已抵港待放行，加上已放行待上架。主壳的 `customsHoldCount` 只计已抵港待放行的**笔数** |
| 已上架次日可售 `shelvedPendingNextDay` | 基准日当天已确认上架的货量，次日才进入可售。历史日与预测日的明细仍遵循 D+1 |
| 预测已发 `projectedInPipeline` | 截至基准日通过校验并已经从预测工厂余额扣减，但缺少实际物流凭据的货量。用于对齐预测流量和库存守恒 |
| 生产待释放 `unreleasedProduction` | 生产区间内按曲线累计、尚待释放的批次产量 |
| 市场预计补货 `incomingQty` | 校验可执行、可售日期在 `(基准日, 预测视窗末日]` 的发运，包括次日将释放的锁定货量及未来计划补货。同日转为可售的数量已从此项移除 |
| 7 日预计上架 `next7DaysExpectedArrivals` | 保留原有 `[基准日, 基准日 + 7]` 上架日期边界。计算可执行且尚无上架事实的推演数量，独立于可售日视窗 |
| 缺口与异常 | 缺口为整个市场在 `[基准日, 基准日 + horizonDays - 1]` 的需求减可满足量。实际物流逾期基于下一个待确认里程碑及其预计日期。阻断为独立异常 |
| 成本 | 保留原来模拟窗口的全量成本。应用发运路线或 SKU 筛选时，物流费按匹配的执行单据加总；无法分摊的综合成本留空 |

实际物流三个货量状态、已上架锁定量、预测已发量、生产待释放量和日终余额对模拟时点的库存构成互斥。各预计事件和区间补货量属于跨日统计，可覆盖已在构成中出现的同一批货。例如今天已上架 20 件，今天锁定 20 件，同时计入视窗内的明日预计可售补货 20 件。

发运指标按源工厂、目标市场和发运记录上的产品 ID 过滤。按路线联合筛选时两个仓点的总体库存均无法归属于该路线，因此可用库存留空。混合 SKU 工作区的仓点余额、需求和生产曲线没有 SKU 维度，显式 SKU 查询只按带产品 ID 的发运及批次确定归属。市场风险保留整体市场语义。原始批次查询返回与日期范围相交的完整批次量。市场关联多条发运的批次总量仍属于完整批次。

## 待业务确认的边界

- **锚点盘点导入**。本实现将日期理解为开盘余额。若实际导入的外部盘点把锚定日早晨从 D+1 转入的货量已计入余额，需要确定导入语义或更细的盘点时间。当前记录只有日期。
- **旧发运离港日缺失**。旧数据若已将计划离港日覆盖成实际日期，只能使用原记录仍保存的计划信息。跳过离港时，推演延续已有规则，用计划日期与最早下游事实中较早的日期定位移动。计划与下游事实分居锚点两侧时，需要实际离港凭据来确认工厂余额是否已反映此笔。
- **实际进展和预测兼容**。历史契约中库存校验通过的发运会进入模拟物流进度。旧 `progressStatus` 与 `isOverdueUnconfirmed` 继续服务该用途。实际物流消费者应读取 `operationalStatus`、`operationalOverdue` 和 `dispatchBasis`。原计划时间消耗可以达 100%，该字段表示日历进度。
- **独立 SKU 库存与成本**。当前节点余额、曲线和需求按仓点记录。需要按 SKU 盘点或分摊成本时，应先确定单独的库存、曲线和成本归属契约。
- **范围外的审计项**。本轮核查的九个 BUG 编号在上述可复现子项均有处理结论。主壳最近工作仍有 H6 的列表截断路径。存储、AI 会话与审计、复制改期操作及 BOM 其余问题保留在原 BUG 清单。
- **页面验收范围**。自动测试覆盖真实引擎、快照、AI 工具及看板和市场视图生成。当前 Chromium 启动缺少实际可执行文件，浏览器端到端操作仍待实机验收。
